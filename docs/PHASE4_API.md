## Evidence attachment repair seam
`buildEvidenceEntries({textCommitment,textReference,file?,remaining})` returns a file entry first (raw-byte hash/file reference) and a text entry last (salted commitment/independent text reference), or one text entry without attachment. Hashes/references are nonzero bytes32; references are distinct; capacity is an integer0..5 sufficient for the entire plan. No supplied request field bypasses contract evidence counts. UI must show both entries, wait/refetch each transaction, and use the text reference in private evidence POST.

Receipt follow-ups preserve the private payload before a fallible chain read. Fresh event reconciliation identifies each entry by dispute, party, hash and reference. Failed refreshes block further contract actions; successful uploads remain unbound drafts until verified. Definitive reverted receipts permit retry, while unknown outcomes preserve the duplicate guard. Private cache writes require the same wallet/session/job and newest request generation after the requests settle.

## Final authorization and retention clarifications

GET job terms permits parties or a fresh current assigned arbiter on this job's unresolved case and logs successful reads; PUT remains parties-only. File/evidence/reason reads retain their specific milestone/case binding. Evidence text persistence represents an already-confirmed entry, including the fifth entry; evidence text and file writes use the chain snapshot clock with `now < evidenceDeadline`.

Rate limits use a shared trusted loopback bucket plus authenticated session-hash buckets, not caller-controlled forwarding headers. This local policy can throttle multiple demo roles together; it is not a production multi-tenant rate-limit design. Errors have shape `{error:{code}}` and the UI maps codes to plain language.

Retention reads current Closed state/chain closure time, accepts due automatic cleanup regardless of the demo reader's party status, or verifies a canonical named-party EIP-191 deletion signature. UUID file keys map to encrypted `.enc` files; all parent boundaries are checked. An interrupted unlink/database operation may leave partial cleanup; revalidation and retry complete the purge while retaining audit metadata. CLI accepts `--request` and `--request-file`; deletion does not alter contracts or erase recipients' copies.
