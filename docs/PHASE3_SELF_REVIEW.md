# Phase 3 self-review

**Status: complete for F-30–F-35 and F-45 in the local contract scope; root-owned final gates are recorded separately.** Tier B stakes, slashing, and salaries are disabled at zero. Public VRF, UI, and privacy backend are outside this phase. The independent reviewer read the final source and frozen tests. I did not edit contracts/tests or execute the build and test commands.

1. **Caller and forwarding:** engine state mutators are escrow-only; the entropy callback is immutable-provider-only. The escrow forwards the actual caller as actor. The additive phase-error regression covers direct-engine denial and the distinction between wrong phase and wrong seat.
2. **Milestone binding:** opening is limited to eligible Submitted/Rejected states and creates a nonzero dispute ID; the public read wrapper checks the job and milestone before forwarding. Tests cover duplicate/misbound IDs and the existing nonsubmitted/invalid-state exits.
3. **Token entry and rollback:** opening and matching deposits use exact balance deltas, code-hash checks, and non-reentrant escrow entrypoints. A failed/fee transfer rolls back engine flags, escrow state, and liabilities. These checks do not model every malicious token or chain behavior.
4. **Draw snapshots:** each first request snapshots eligible registry candidates; retry requests retain that list. Request IDs are nonzero/global and phase/timer state is reserved before adapter calls. Tests cover registry edits while pending and retry snapshot reuse.
5. **Callback and retry rules:** only the immutable adapter can call back; unknown, duplicate, stale, nonpending, and late callbacks cannot alter active state. A synchronous callback stores entropy only. Two retries follow the initial attempt; request failure remains pending, and ready entropy stays consumable after the deadline.
6. **Panels and no-shows:** selection is distinct and excludes parties. There is at most one replacement request for missing commits; sparse replacements leave vacancies empty and use one shared commit window. Panel 2 excludes all Panel 1 history and has no replacement path.
7. **Commit/reveal rights:** the A-33 commitment binds chain, escrow, dispute, actor, bps, and salt. Registry removal does not revoke a selected seat; a displaced noncommitter cannot vote after replacement. Bps endpoints and wrong-phase/wrong-seat errors have focused tests.
8. **Time and exits:** actor windows are half-open; due advancement begins at the end. Tests hit key E−1/E/E+1 boundaries for evidence, commit, reveal, callback, replacement, and dispute opening. The invariant's bounded trace campaign is intentionally narrower than all possible interleavings; other tests cover retry and fallback branches.
9. **Ruling/accounting:** three votes use median and two use floored mean. Tests cover odd raw amounts, 6/8/18 decimals, normal and fallback splits, per-party floor forfeiture, absent-deposit deductions capped by principal, treasury aliasing, and 0/10,000-bps endpoints.
10. **Liability closure:** settlement performs no token call, credits claims, removes locked principal and posted deposits once, and closes only after the final terminal milestone. Tests cover duplicate terminal attempts, token failure/code drift, and a separate sibling milestone.
11. **Read/event surface:** ABI and read shapes are recorded in `docs/PHASE3_API.md`; event ownership is split between engine state events and escrow money/job events. The two-address indexing requirement is documented. No wallet/UI end-to-end review is claimed.
12. **Recorded gates:** root's final evidence reports optimized compile success (29 source units/32 artifacts/0 errors), forced Forge compilation of 64 files, 109 tests passed/0 failed/0 skipped, successful public-build guard cases, six frozen integrity checks unchanged, dependency audit with zero vulnerabilities, and the secret scan passing. Coverage is 99.09% engine lines/74.77% branches, 99.33% escrow lines/86.67% branches, and 69.18% overall branches.
